# SeedQR Tool

A KeyOS SDK app for Passport Prime. It helps you copy a SeedQR onto a durable
medium by hand, then checks the copy you made decodes back to the seed you
started with.

## What it does

1. **Welcome.** Load a seed by scanning an existing SeedQR, or by typing 12 or 24
   words with BIP39 autocomplete.
2. **Format.** Standard (25x25 for 12 words, 29x29 for 24) or Compact (21x21 and
   25x25). The app re-encodes from the seed, so you can scan a Standard code and
   transcribe a Compact one.
3. **Overview.** The whole code at whole-pixel scale, for orientation.
4. **Transcribe.** The code walked in 7x7 blocks. Each screen shows the row and
   column range, and a mini-map with the active block outlined. Grey cells fall
   outside the code.
5. **Verify.** Scan the copy you made. It is compared against the seed loaded at
   the start and reported as a match, a different seed, or not a SeedQR.

## Nothing is stored

The seed lives in memory for one session. The manifest requests no filesystem
write permission, so the app cannot persist it even by mistake. `AppState::clear`
scrubs the typed words, and the seed itself is a `security::Seed`, which zeroizes
on drop.

The app never touches the camera. Scanning goes through the system QR Scanner as
a fullscreen modal (`open_qr_scanner`), which needs only `ShowModal`.

An SDK app cannot read the device master key or seeds held by other apps, so this
cannot transcribe a seed stored in Seed Vault. The seed has to come in from
outside.

## Build

Everything runs inside the SDK Nix shell:

```bash
cd ~/Documents/AI/keyos-seedqr-transcribe && nix develop ~/.foundation/sdk/foundation-sdk-1.0.0-aarch64-apple-darwin --command foundation pack --release
```

Signed with the `passport-prime-dev` identity. Publisher fingerprint:

```text
19be3035a84826e7732fc07f56c62175ef3a0f4a86fb63a80cf73f93c4f56cfb
```

Outputs land in `target/keyos/`:

- `keyos-seedqr-transcribe.app` — one archive, install from **Settings > Apps > Install App**
- `keyos-seedqr-transcribe/` — the loose bundle, for `foundation sideload`

## Layout

| Path | What |
|---|---|
| `ui/globals.slint` | `SeedState` (values Rust pushes) and `Actions` (callbacks Rust implements) |
| `ui/pages/` | One directory per route, each with `props.slint` and `page.slint` |
| `ui/gen/` | Router, generated by the build script. Not edited by hand. |
| `crates/seedqr-core/` | Grid geometry and block maths. No KeyOS or Slint dependency, so it tests on the host. |
| `src/seedqr.rs` | SDK payload encoding and image rendering |
| `src/app.rs` | App state and callback wiring |

Navigation stays in Slint. Callbacks that can fail return a bool so the page only
moves on success.

## Tests

```bash
cargo test -p seedqr-core
```

Nine tests over the grid geometry, using SeedSigner's own 12 and 24 word test
vectors:

- Payload lengths (48, 96 digits; 16, 32 bytes) and grid sizes (25x25, 29x29,
  21x21, 25x25) match the spec.
- Error correction level L is load bearing for the compact format. A 16 byte
  payload fits a 21x21 at L and not at M, and 32 bytes fits a 25x25 at L and not
  at M, so building at the wrong level silently produces an oversized grid.
  Standard payloads happen to fit at either level at these sizes.
- Every module in all four grids appears in exactly one block, no gaps and no
  duplicates, and each cell reports the right colour.
- Blocks are always a full square of cells, extents are 1-based and clamped to
  the code edge, out of range reads return light rather than panicking.

## Also checked

- `foundation doctor` passes inside the project.
- Builds, signs, packs and launches in the KeyOS simulator with no runtime error
  and no permission denial.
- The signed `manifest.json` grants read-only `os/fs` (no `WriteFile`,
  `CreateDirMessage`, `Flush` or `Remove`), `os/gui-server` and theme-only
  `os/settings`. No `os/security`, no `os/camera`. The scanner call is
  compile-time gated on `MessageAllowed<ShowModal>`, so a successful build
  proves that permission is present.

## Not verified

- **Nothing on hardware.** Scan, verify, word entry and block navigation have
  never run against a real camera or touchscreen.
- **No screen has been looked at.** The app launches without error, but the
  simulator has no scriptable screenshot and its window is not reachable by the
  screen tooling here, so nothing confirms the pages actually render as intended.
- **No UI or integration tests.** The app crate builds only for
  `armv7a-unknown-xous-elf`, so nothing in `src/` is covered by a test. The
  callbacks in `src/app.rs` have never been executed.
- **Strings are hardcoded English.** No `i18n/` and `include_translations: false`,
  matching the SDK template. It would need localizing before shipping to users.
